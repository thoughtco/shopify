There are a few tags included in the addon that help you get the information you need to the frontend.

## Tokens

Allows you to output your Site URL and Storefront Token to the front end and binds them to the window so you can use them in the JS SDK. If you are using a custom storefront url instead of a myshopify.com domain, you can specify that with the `storefront_url` key the `config/shopify.php`.

#### Usage

```twig
{{ shopify:tokens }}
```

#### Output

```html
<script>
  window.shopifyConfig = {"url":"your-site.myshopify.com","token":"storefront-token","apiVersion":"2026-01","currency":"£"};
</script>
```

#### Multi-Store

In [unified or localized multi-store mode](/cms/sites-and-stores/multi-store) pass the `store` param to output that store's credentials. A `currency` key is also included, sourced from the store's config:

```twig
{{ shopify:tokens store="uk" }}
```

```html
<script>
  window.shopifyConfig = {"url":"uk-store.myshopify.com","token":"uk-storefront-token","apiVersion":"2026-01","currency":"£"};
</script>
```

#### Markets Mode

In [markets mode](/cms/sites-and-stores/multi-store#markets-mode) pass a country code as the `store` param. The single store's URL and storefront token are used, but the `currency` is sourced from the matching market's config:

```twig
{{ shopify:tokens store="GB" }}
```

```html
<script>
  window.shopifyConfig = {"url":"your-store.myshopify.com","token":"storefront-token","apiVersion":"2026-01","currency":"£","market":"GB"};
</script>
```

The bundled Alpine.js integration reads `window.shopifyConfig.currency` automatically for currency formatting.

With `shopify.cart.buyer_identity` enabled, the config also has `"buyerIdentityUrl":"/!/shopify/buyer"`, telling the cart JS where to fetch a logged in customer's details. The details themselves are never output, so the tag stays safe to use on statically cached pages. See [Pre-filling checkout](/frontend/getting-started/storefront-api#pre-filling-checkout-for-logged-in-customers).

## Product Price

#### Usage

```twig
{{ shopify:product_price show_from="true" }}
```

- `show_from`: display a "From " prefix to the price if there are multiple variants.
- `slug`: optional, the product slug to look up variants for. Defaults to the `slug` in the current context, so you only need this when rendering the tag outside of a product entry.
- `subscription`: optional, `true` for the lowest price on any [selling plan](/frontend/getting-started/subscriptions#subscription-prices).
- `selling_plan`: optional, a selling plan id for the price on that plan.

#### Output

If the product is out of stock returns `out of stock`. 

If not, returns the lowest price of a product. 

```html
Out of Stock

// or

From £50.00 

// or 

£4.99
```

#### product-price hook

This tag provides a [Hook](https://statamic.dev/extending/hooks) to modify the price and currency. For example, if you wanted to format the price using PHP's NumberFormatter:

```php
\Thoughtco\Shopify\Tags\Shopify::hook('product-price', function ($payload, $next) {
    $formatter = new \NumberFormatter(\Statamic\Facades\Site::current()->locale(), \NumberFormatter::CURRENCY);

    $payload->price = $formatter->formatCurrency((float) $payload->price, 'EUR');
    
    return $next($payload);
});
```

## Selling Plans

Outputs the product's subscription and other purchase options, priced. See [Subscriptions](/frontend/getting-started/subscriptions#listing-plans).

#### Usage

```antlers
{{ shopify:selling_plans variant="123" }}
    {{ plans }}{{ group_name }}: {{ name }} {{ price }}{{ /plans }}
{{ /shopify:selling_plans }}
```

- `slug`: optional, the product slug. Defaults to the product in context.
- `variant`: optional, a variant id for just that variant's plans.
- `store`: optional, the store or market on multi-store and markets sites.

## Product Variants

You can interact with the variants in several ways. In the demo theme we output this automatically, but you may want to drill down deeper.

### Generate

If you want a simple way to include the variants a tag has been made to load them in. This will either output a select or hidden input depending on how many variants you have.

#### Usage

```twig
{{ shopify:variants:generate show_price="true" show_out_of_stock="true" class="border" }}
```

This will automatically use the `slug` from the context of the post to fetch the variants.

- `show_price`: optional, will use the currency from the config file.
- `show_out_of_stock`: optional, will use the "Out of Stock" lang from the config file.
- `class`: optional, allows you to pass classes down to the select.
- `slug`: optional, the product slug to look up variants for. Defaults to the `slug` in the current context, so you only need this when rendering the tag outside of a product entry.

#### Output

```html [Singular]
<input type="hidden" name="ss-product-variant" id="ss-product-variant" value="STOREFRONT_ID" />
```

```html [Multiple]
<select name="ss-product-variant" id="ss-product-variant" class="ss-variant-select">
  ...
  <option value="STOREFRONT_ID">TITLE - PRICE</option>
  <option value="STOREFRONT_ID">TITLE - PRICE</option>
  ...
</select>
```

### Loop

If you want a bit more manual control over how to handle the variants, you can use the `loop` method.

#### Usage

```twig
{{ shopify:variants }}
    {{ title }}
{{ /shopify:variants }}
```

You can use [tag conditions](https://statamic.dev/conditions) to filter the variants returned, for example:

```twig
{{ shopify:variants title:is="my_title" }}
    {{ title }}
{{ /shopify:variants }}
```

- `slug`: optional, the product slug to look up variants for. Defaults to the `slug` in the current context, so you only need this when rendering the tag outside of a product entry.


## In Stock

Check if a product is in stock or not.

#### Usage

```twig
{{ shopify:in_stock }}
```

```twig
{{ if {shopify:in_stock} }}
   ...
{{ /if }}
```

- `slug`: optional, the product slug to check stock for. Defaults to the `slug` in the current context, so you only need this when rendering the tag outside of a product entry.

## Customer

Return the Shopify customer data for the current logged in user. If nobody is logged in, `{{ not_found }}` is set.

These tags query the Shopify Admin API, which can read **every** customer, address and order in the store. When you call `{{ shopify:customer }}` with no parameter it is scoped to the logged in user, but the `customer_id` parameter is not — whatever ID you pass is fetched as-is. Never build `customer_id` (or a rendered order ID) from a request parameter without first checking it belongs to the logged in user, or you will expose other customers' data.

#### Usage

```twig
{{ shopify:customer }} ... {{ /shopify:customer }}
```

## Customer Addresses

Return the Shopify addresses for the current logged in user, the default address first.

#### Usage

```twig
{{ shopify:customer:addresses }}
    {{ addresses }}
        {{ firstName }} {{ lastName }}, {{ address1 }}, {{ city }} {{ zip }}, {{ country }}
        {{ if default }}(default){{ /if }}
    {{ /addresses }}
{{ /shopify:customer:addresses }}
```

Each address has `id`, `firstName`, `lastName`, `company`, `address1`, `address2`, `city`, `province`, `provinceCode`, `country`, `countryCode`, `zip`, `phone`, `name` and `default` (whether it's the customer's default address). `addresses_count` is the number of addresses.

## Customer Address Form

Creates a form that directs to the appropriate endpoint for processing a customer address.

The address endpoints require an authenticated Statamic user and always act on that user's linked Shopify customer, so this form only works for logged in users.

#### Usage

```twig
{{ shopify:address_form }} ... {{ /shopify:address_form }}
```

```twig
{{ shopify:address_form address_id="address_id_to_edit" }} ... {{ /shopify:address_form }}
```

The form takes `firstName`, `lastName`, `address1`, `city`, `zip` and `countryCode` (required), and `company`, `address2`, `provinceCode`, `phone` and `default` (`1` to make it the default address). Shopify's Admin API takes ISO codes for the country and province, not names: `countryCode="GB"`, `provinceCode="CA"`. For backwards compatibility, `country` and `province` are still accepted when they hold codes. Inside `{{ shopify:customer:addresses }}`, prefill an edit form from the address:

```twig
{{ shopify:customer:addresses }}
    {{ addresses }}
        {{ shopify:address_form :address_id="id" redirect="/account/addresses" }}
            <input name="firstName" value="{{ firstName }}">
            <input name="lastName" value="{{ lastName }}">
            <input name="address1" value="{{ address1 }}">
            <input name="city" value="{{ city }}">
            <input name="zip" value="{{ zip }}">
            <select name="countryCode">
                <option value="GB" {{ countryCode == 'GB' ?= 'selected' }}>United Kingdom</option>
                <option value="IE" {{ countryCode == 'IE' ?= 'selected' }}>Ireland</option>
            </select>
            <input name="provinceCode" value="{{ provinceCode }}">
            <label><input type="checkbox" name="default" value="1" {{ default ?= 'checked' }}> Default address</label>
            <button>Save address</button>
        {{ /shopify:address_form }}
    {{ /addresses }}
{{ /shopify:customer:addresses }}
```

To delete an address, send a `DELETE` to `/!/shopify/address/{id}`, e.g. a form with `{{ csrf_field }}` and `<input type="hidden" name="_method" value="DELETE">` posting to `{{ route:statamic.shopify.address.destroy :id="id" }}`.

On [multi-store](/cms/sites-and-stores/multi-store#customers) sites, add `store="uk"` so the address is saved to the customer in that store.

You can optionally specific `redirect` and `error_redirect` params to be taken to a different page on success or error respectively. Off-site URLs are ignored.

Any errors during processing will be available in the `{{ errors }}` variable. 


## Customer Orders

Return the Shopify orders for the current logged in user.

#### Usage

```twig
{{ shopify:customer:orders }} ... {{ /shopify:customer:orders }}
```

This tag also supports pagination:

```twig
{{ shopify:customer:orders paginate="10" }} ... {{ /shopify:customer:orders }}
```

You can sort the orders using the `sort` parameter, in the format `field:direction` (direction is `asc` or `desc`, defaulting to `asc`):

```twig
{{ shopify:customer:orders sort="created_at:desc" }} ... {{ /shopify:customer:orders }}
```

Sorting is done by Shopify, so the available fields are those in Shopify's [OrderSortKeys](https://shopify.dev/docs/api/admin-graphql/latest/queries/orders#arguments-sortKey): `created_at`, `customer_name`, `destination`, `financial_status`, `fulfillment_status`, `id`, `order_number`, `po_number`, `processed_at`, `total_items_quantity`, `total_price` and `updated_at`. Any other value is ignored.

Each order has `id`, `name` (e.g. `#1001`), `createdAt`, `displayFinancialStatus`, `displayFulfillmentStatus`, `cancelledAt`, `cancelReason`, `discountCodes`, `requiresShipping`, `statusPageUrl` (Shopify's order status page), `billingAddress`, `shippingAddress`, `lineItems:nodes` (each with `id`, `title`, `quantity`, `sku`, `image:url`, `originalUnitPriceSet`, `discountedUnitPriceSet`, `product:handle`, `variant` (`id` and `availableForSale`, or null if the variant has been deleted), `sellingPlan` (`sellingPlanId` and `name`, for a subscription) and `customAttributes`), `fulfillments` (the order's shipments, below) and the amounts `subtotalPriceSet`, `totalShippingPriceSet`, `totalTaxSet`, `totalDiscountsSet`, `totalPriceSet` and `totalReceivedSet`. Each amount's `presentmentMoney` is in the currency the customer paid in: format it with the [`shopify_money`](#money) modifier.

#### Shipments

Each of an order's `fulfillments` (up to 10) has `displayStatus` (e.g. `IN_TRANSIT`, `DELIVERED`), `createdAt`, `inTransitAt`, `estimatedDeliveryAt`, `deliveredAt` and `trackingInfo` (up to 5, each with `company`, `number` and `url`; `url` can be null when Shopify doesn't know the carrier):

```twig
{{ fulfillments }}
    {{ displayStatus | replace('_', ' ') | lower | ucfirst }}, sent {{ createdAt | format('j F') }}
    {{ trackingInfo }}
        {{ company }}: {{ if url }}<a href="{{ url }}">{{ number }}</a>{{ else }}{{ number }}{{ /if }}
    {{ /trackingInfo }}
{{ /fulfillments }}
```

#### Buying an order again

The line items carry what the cart needs to add them again, so a "Buy again" button can pass them to the cart store's [`addItems()`](/frontend/getting-started/storefront-api#adding-several-lines):

```twig
<button x-data="{ lines: {{ lineItems:nodes | where('variant.availableForSale', true) | to_json | entities }} }" @click="$store['statamic.shopify.cart'].addItems(lines)">
    Buy again
</button>
```

## Customer Order

Return one of the logged in user's orders, with the same fields as `{{ shopify:customer:orders }}`, for an order page.

#### Usage

```twig
{{ shopify:customer:order :id="segment_3" }}
    {{ if not_found }}
        That order isn't in your account.
    {{ else }}
        {{ name }}: {{ totalPriceSet:presentmentMoney | shopify_money }}
        {{ lineItems:nodes }}{{ quantity }} × {{ title }}{{ /lineItems:nodes }}
    {{ /if }}
{{ /shopify:customer:order }}
```

`id` is the order's numeric ID (the `id` from `{{ shopify:customer:orders }}`) or its GID. The tag checks that the order belongs to the logged in user's Shopify customer, so the ID can safely come from the URL: an order belonging to someone else, one that doesn't exist, an ID that isn't a number and a guest all get `not_found`. On [multi-store](/cms/sites-and-stores/multi-store#customers) sites, add `store="uk"`.

## Money

The `shopify_money` modifier formats an amount in its own currency, such as an order's totals, which are in the currency the customer paid in:

```twig
{{ totalPriceSet:presentmentMoney | shopify_money }}   {{# €12.50 #}}
{{ amount | shopify_money('USD') }}                    {{# $9.99 #}}
```

It takes a Shopify money value (`{ amount, currencyCode }`), or an amount with a currency code (the store's `currency_code` if left out), and formats it for the current site's locale with PHP's intl extension. Without intl it shows the store's `currency` symbol for its own currency, and the code otherwise ("12.50 EUR").
