title: Subscriptions
---

Once [selling plans are imported](/cms/importing/selling-plans), you can show a product's subscription options, let customers choose between a one-off purchase and a subscription, and add the chosen plan to the cart. Checkout and managing subscriptions afterwards are handled by Shopify and your subscription app.

Your Storefront API token needs the `unauthenticated_read_selling_plans` scope.

## Listing plans

`{{ shopify:selling_plans }}` outputs the plans for the product in context, or the product with the `slug` param. Pass `variant` (a variant id) for just that variant's plans, and `store` on multi-store and markets sites.

```antlers
{{ shopify:selling_plans }}
    {{ if has_selling_plans }}
        {{ groups }}
            <h3>{{ name }}</h3>
            {{ selling_plans }}
                <p>{{ label }}: {{ price }}</p>
            {{ /selling_plans }}
        {{ /groups }}
    {{ /if }}
{{ /shopify:selling_plans }}
```

| Variable | |
|---|---|
| `requires_selling_plan` | The product can only be bought on a plan |
| `has_selling_plans` | There's at least one plan |
| `groups` | The groups, each with `name`, `app_id`, `options` and `selling_plans` |
| `plans` | Every plan in one list, each with its `group_name` |

Each plan has the [imported values](/cms/importing/selling-plans#whats-imported) plus:

| Variable | |
|---|---|
| `label` | The plan's option values, e.g. "Deliver every 2 months", or its `name` if it has none. Use this rather than `name` in markets mode (see below). |
| `price` | The formatted price on the plan, from the lowest priced variant that can be bought on it |
| `price_amount` | The same as a number |
| `adjustment_type`, `adjustment_value` | The discount on the first delivery, e.g. `PERCENTAGE` and `10` |

Plans none of the product's variants can be bought on aren't listed.

> [!WARNING]
> Some apps write the discount into the plan's name in your shop's currency: Shopify Subscriptions names a plan "Deliver every 2 months, £3.00 off". In markets mode that text is wrong for every other market, and it doesn't change when the market does. Show `label` instead, and the saving from the market's prices (the one-off price minus `price`).

## Subscription prices

`{{ shopify:product_price }}` shows the one-off price. For the price on a plan:

```antlers
{{ shopify:product_price subscription="true" }}  {{# the lowest price on any plan #}}
{{ shopify:product_price selling_plan="gid://shopify/SellingPlan/123" show_from="true" }}
```

Prices use the first delivery's pricing policy: a percentage off, a fixed amount off or a fixed price. Nothing is output when no variant can be bought on a plan.

In markets mode, with `store="IE"` on the tags (or an active market in `shopifyProduct`), prices are the exact market prices imported from the Storefront API, so they match checkout. See [Multi-store and markets](/cms/importing/selling-plans#multi-store-and-markets) for what's needed, and the fallback when a market has no imported prices.

## Adding to the cart

Pass the tag's output to `shopifyProduct` as a third argument, and it gains a one-off / subscribe toggle and a plan picker. `handleSubmit` sends the chosen plan with the cart line (`sellingPlanId`):

```antlers
{{ $variants = {shopify:variants} }}
{{ $plans = {shopify:selling_plans} }}
<div x-data='shopifyProduct({{ options | to_json }}, {{ $variants | to_json }}, {{ $plans | to_json }})'>
    <form @submit.prevent="handleSubmit($event.target)">
        {{ shopify:variants:generate }}

        <template x-if="hasSellingPlans()">
            <div>
                <label x-show="! requiresSellingPlan">
                    <input type="radio" value="one_time" :checked="purchaseType === 'one_time'" @change="setPurchaseType('one_time')">
                    One-off purchase
                </label>
                <label>
                    <input type="radio" value="subscription" :checked="purchaseType === 'subscription'" @change="setPurchaseType('subscription')">
                    Subscribe
                </label>

                <select x-show="purchaseType === 'subscription'" @change="selectSellingPlan($event.target.value)">
                    <template x-for="plan in availableSellingPlans()" :key="plan.id">
                        <option :value="plan.id" x-text="plan.label" :selected="plan.id === currentSellingPlan()?.id"></option>
                    </template>
                </select>

                <span x-show="getSellingPlanPrice() !== null" x-text="Alpine.store('statamic.shopify.cart').formatCurrency(getSellingPlanPrice())"></span>
            </div>
        </template>

        <input type="number" min="1" value="1" x-ref="qty">

        <button type="submit" :disabled="! (allOptionsSelected() && variantExistsAndIsInStock() && sellingPlanSatisfied())">Add to cart</button>
    </form>
</div>
```

| Property / method | |
|---|---|
| `purchaseType` | `'one_time'` or `'subscription'` |
| `requiresSellingPlan` | The product can only be bought on a plan. `purchaseType` starts as, and stays, `'subscription'`. |
| `availableSellingPlans()` | The plans the selected variant can be bought on |
| `hasSellingPlans()` | Whether the selected variant has any plans |
| `setPurchaseType(type)` | Switch between one-off and subscription (picks the first plan if none is chosen) |
| `selectSellingPlan(id)` | Choose a plan |
| `currentSellingPlan()` | The plan that will be added: the chosen one if the selected variant has it, otherwise its first plan. `null` for one-off purchases. |
| `syncPurchaseType()` | Switches back to a one-off purchase when the selected variant has no plans (unless the product requires one). Runs whenever the selected variant changes. |
| `sellingPlanSatisfied()` | `false` when the product requires a plan but the selected variant has none. `handleSubmit` won't add it. |
| `getSellingPlanPrice(plan, variant)` | The price on a plan as a number (defaults to the current plan and selected variant), or `null` when it can't be worked out. In markets mode, the imported price for the active market. |

Without the third argument `shopifyProduct` works as before.

## In the cart

Each line in `Alpine.store('statamic.shopify.cart').lineItems` has a `sellingPlan` (`{ id, name, label }`, or `null` for one-off purchases), and the line's price is the price on the plan. Show `label` (the plan's options, e.g. "Deliver every 2 months"): `name` may include the discount in your shop's currency (see above):

```antlers
<span x-show="line.sellingPlan" x-text="line.sellingPlan?.label"></span>
```

If you use `cart.js` directly, the cart query now includes each line's `sellingPlanAllocation` (the plan and its `priceAdjustments`), and `addLines` takes a `sellingPlanId` on each line:

```js
await addLines(cartId, [{ merchandiseId, quantity: 1, sellingPlanId: 'gid://shopify/SellingPlan/123' }]);
```

`resources/js/shopify/selling-plans.js` has the helpers the component uses (`sellingPlansForVariant`, `sellingPlanPrice`, `sellingPlanLabel`) if you're building your own.

## In customer accounts

`{{ shopify:customer:subscriptions }}` lists the logged in customer's subscriptions, so an account page can show what they're subscribed to and link to your subscription app's portal to change it.

Shopify only lets the app that created a subscription read it: the addon can't read subscriptions made by Shopify Subscriptions, Recharge or any other app. Instead, it works them out from the orders that started them, and two Shopify Flow workflows that come with the addon keep each subscription's status on its first order.

### Setting up the workflows

The workflows are in the addon's [`resources/flow`](https://github.com/thoughtco/shopify/tree/main/resources/flow) folder (also in `vendor/thoughtco/shopify/resources/flow`):

- `create.flow` runs when a subscription is created. It writes the subscription onto its first order and tags that order `Subscription First Order`.
- `update.flow` runs when a subscription changes (paused, resumed, cancelled, a new billing date) and updates what's on the order.

Each workflow has one trigger, so import them separately. In your Shopify admin, open the [Shopify Flow](https://apps.shopify.com/flow) app, choose **Import**, pick a file, then **Turn on workflow**. Do the same with the other one.

Each subscription is stored as a JSON metafield on its first order, in the `statamic_subscriptions` namespace, keyed by the subscription's ID (`contract_86387654954`):

```json
{
    "id": "gid://shopify/SubscriptionContract/86387654954",
    "status": "ACTIVE",
    "nextBillingDate": "2027-01-25T13:00:00Z",
    "lines": [{ "variantId": "gid://shopify/ProductVariant/46537622061354", "sellingPlanId": "gid://shopify/SellingPlan/11344970026" }]
}
```

Subscriptions created before you turn the workflows on aren't written until they next change.

Without the workflows, the tag still lists the subscriptions from orders your subscription app tags, but without their status or next billing date. Shopify Subscriptions tags a subscription's first order `Subscription First Order`. If your app uses a different tag (and you haven't imported the workflows, which add ours), set it in `config/shopify.php`:

```php
'subscriptions' => [
    'order_tag' => env('SHOPIFY_SUBSCRIPTION_ORDER_TAG', 'Subscription First Order'),
],
```

### Listing subscriptions

```antlers
{{ shopify:customer:subscriptions status="active|paused" }}
    {{ subscriptions }}
        {{ sellingPlan:name }}{{ if status }}: {{ status | lower | ucfirst }}{{ /if }}
        {{ if nextBillingDate }}Next order {{ nextBillingDate | format('j F Y') }}{{ /if }}
        {{ lines }}{{ quantity }} × {{ title }}{{ /lines }}
        Started with order {{ order:name }}
    {{ /subscriptions }}
{{ /shopify:customer:subscriptions }}
```

### Managing subscriptions

Customers pause, skip and cancel subscriptions in your subscription app's portal. Set its URL to output it as each subscription's `manage_url`:

```bash
SHOPIFY_SUBSCRIPTION_MANAGE_URL="https://shopify.com/12345678901/account/pages/your-page-id"
```

For Shopify Subscriptions, it's the Subscriptions page in your Shopify customer accounts (as above): sign in to your store's account as a customer with a subscription and copy its address. If your app has a page for each subscription, use `{id}` for the subscription's ID (`https://example.com/subscriptions/{id}`); `manage_url` is then null until the workflows have written the subscription.

```antlers
{{ if manage_url }}<a href="{{ manage_url }}">Manage subscription</a>{{ /if }}
```

See the [tag reference](/frontend/reference/tags#customer-subscriptions) for all the fields. Renewal orders aren't listed: only the order each subscription started with.
