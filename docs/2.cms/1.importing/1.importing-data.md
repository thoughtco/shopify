title: Importing Data
---

The import jobs have been written to pull in your products and sort out all the data. It's advisable that you use a queue system such as Redis. You can either pull all products or a single product.

## Via the Admin

These methods can be accessed through the CMS by finding the **Shopify** section under the **Tools** heading.

> [!NOTE]
> You may need to clear your cache after the import. Use `php please cache:clear` to ensure everything is a-okay.

#### All Products

Fetch all products by clicking the **Import All** button under the Import Products section.

#### Single Product

Fetch a single product by searching for the product in the select and then clicking the **Import Product** button under the Import Single product section. 

#### From the products listing or an entry

Use the **Reimport from Shopify** action to update products with their latest data from Shopify:

- On a product entry, from the actions menu at the top of the page.
- In the products listing, from a product's actions menu, or select several products and choose **Reimport** from the bulk actions bar.

Each product is queued for import separately, and you can follow progress under **Shopify > Activity**. The action is only offered for products that came from Shopify (those with a `product_id`), and needs the **Manage Shopify Imports** (`access shopify`) permission.

## Via Command Line

> [!NOTE]
> You may need to clear your cache after the import. Use `php please cache:clear` to ensure everything is a-okay.

#### All Products

Fetches all products and runs them through the updater.

```bash
php artisan shopify:import:all
```

In [multi-store mode](/cms/sites-and-stores/multi-store) you can target a specific store with the `--store` option, or omit it to iterate all configured stores:

```bash
php artisan shopify:import:all --store=uk
php artisan shopify:import:all --store=us
php artisan shopify:import:all   # imports from all stores
```

#### Single Product

Fetch a single product by their ID. You can find the ID from the `product_id` value stored on the content.

```bash
php artisan shopify:import:product ID_HERE
```

In multi-store mode you can specify the store the product belongs to:

```bash
php artisan shopify:import:product ID_HERE --store=uk
```

## Import Failures

When an import job fails after all retries are exhausted, two things happen automatically:

1. The error is written to your Laravel log with the product ID and, in multi-store mode, the store handle.
2. A `ProductImportFailed` event is fired, which you can listen for to add your own handling (notifications, alerts, etc.).

```php
use Thoughtco\Shopify\Events\ProductImportFailed;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        Event::listen(ProductImportFailed::class, function (ProductImportFailed $event) {
            // $event->productId   — the Shopify product ID
            // $event->storeHandle — the store handle (null in single-store mode)
            // $event->exception   — the Throwable that caused the failure
        });
    }
}
```

## API Rate Limiting

The importer automatically handles Shopify's GraphQL API throttling. After each query, it inspects the `extensions.cost.throttleStatus` returned by Shopify. If the available query budget drops below 500 points, the importer pauses briefly (calculated from Shopify's restore rate) before continuing.

This means large imports will slow down gracefully rather than hitting hard API errors. No configuration is required.

## Image Alt Text

Alt text is imported from Shopify alongside each product and variant image. When an image is first downloaded, its alt text is saved to the Statamic asset's `alt` field. On subsequent imports, if the alt text has changed in Shopify it will be updated on the existing asset.

## Published state

By default the `published` state and `published_at` of the product is determined by the values of `Online Store` sales channel. If you want to use a different sales channel to determine availability you can specify the name of the channel in the `SHOPIFY_SALES_CHANNEL` env variable, e.g. `SHOPIFY_SALES_CHANNEL="My other channel"`.

## Sales channel filtering

By default all Shopify products are imported regardless of whether they are assigned to the configured sales channel. To restrict imports to only products on the sales channel, set `import_all_products` to `false` in `config/shopify.php`:

```php
'import_all_products' => false,
```

When this is enabled, any product that is not assigned to the configured sales channel will be skipped. If a product was previously imported and is later removed from the sales channel, it and all of its variants will be deleted from Statamic on the next import.

## Metafields

Any product and variant meta fields will be automatically added to the Statamic entry data, with the same handle as their key in Shopify and using the raw value.

### Metaobjects

Metafields that reference [metaobjects](https://help.shopify.com/en/manual/custom-data/metaobjects) (`metaobject_reference` and `list.metaobject_reference`) are imported as the metaobject's data, rather than its ID. This works for product, variant and collection metafields, and needs the `read_metaobjects` access scope.

A metaobject becomes an array of its fields, keyed by field key, plus its `handle` and `type`. A list of metaobjects becomes an array of those:

```yaml
designer:
  name: Ada
  photo: 'https://cdn.shopify.com/s/files/ada.jpg'
  studio:
    city: London
    handle: studio-ada
    type: studio
  handle: ada
  type: designer
features:
  -
    label: Waterproof
    handle: waterproof
    type: feature
  -
    label: Lightweight
    handle: lightweight
    type: feature
```

So a single metaobject suits a [group](https://statamic.dev/fieldtypes/group) or [array](https://statamic.dev/fieldtypes/array) field and a list suits a [grid](https://statamic.dev/fieldtypes/grid), or a [replicator](https://statamic.dev/fieldtypes/replicator) with a set per metaobject type (each item's `type` is the set handle). Within a metaobject:

- File and image fields are imported as the file's URL (they aren't downloaded as assets).
- A field referencing another metaobject is imported the same way, one level deep. Metaobjects referenced from that one are left as their ID.
- List fields are arrays. Other fields keep Shopify's value, as metafields do, and the `handle` and `type` keys take precedence over fields with those keys.

The metaobjects are fetched after the product, in one query for all of a product's and its variants' metafields (25 metaobjects per query, up to 25 items per list field), so they don't add to the cost of the product query. If they can't be fetched, for example because the app doesn't have the `read_metaobjects` scope, a warning is logged and the metafield is imported as the metaobject's ID, as before. To turn this off, set `SHOPIFY_RESOLVE_METAOBJECTS=false` (`metaobjects.resolve`).

#### Importing metaobjects into a collection

To keep the metaobjects of a definition themselves in Statamic, for example to give each designer a page, import them into a collection. Map each metaobject definition type to a collection in `config/shopify.php`, and create the collections first:

```php
'metaobjects' => [
    'collections' => [
        'designer' => 'designers',
        'studio' => 'studios',
    ],
],
```

```bash
php artisan shopify:import:metaobjects                  # every type in metaobjects.collections
php artisan shopify:import:metaobjects designer
php artisan shopify:import:metaobjects designer --collection=people
php artisan shopify:import:metaobjects designer --store=uk
```

A type that isn't mapped (and has no `--collection`) is imported into a collection with the same handle as the type. Each type gets its own collection because metaobject handles are only unique within a type. Each metaobject is saved as an entry with its handle as the slug, its display name as the title, its fields as above, `metaobject_id` and `metaobject_type`. Running the command again updates the entries it created, found by `metaobject_id`. Metaobjects deleted in Shopify aren't removed, and the command runs straight away rather than on the queue.

### Custom parsers

You can specify a custom metafield parser to modify the data returned by Shopify before it is saved. This class is specified by `metafields_parser` in `config/shopify.php`. Your custom parser should have an execute method that expects parameters of an array of metafields, a string for the context (product, product-variant or collection), and it should return an array keyed by the handle of the field you want to save to in Statamic.

```php
<?php

namespace App\Shopify;

class MyMetafieldParser
{
    /**
     * Parse any metafields
     *
     * @return array
     */
    public function execute(array $metafields, string $context)
    {
        // do something with $metafields
        return ['key' => 'value', 'another_key' => 'another_value'];
    }
}
```

Each metafield has its `key`, `type`, `value` and `jsonValue`. Metaobject references also have the metaobject under `reference` (or `references.nodes` for a list) with its `id`, `handle`, `type`, `displayName` and `fields` (each with `key`, `type`, `value`, `reference` and `references`). To keep the default handling of metaobjects in your own parser, extend `Thoughtco\Shopify\Actions\ParseMetafields`, or call its `metaobject()` method with a metaobject.

We have provided a helper to convert Shopify's Rich Text meta field type to either HTML or Bard, which you can use as follows:

```php

// html
$html = (new Thoughtco\Shopify\Support\RichTextConverter)->convert($metafield['value']);

// bard
$bard = (new Thoughtco\Shopify\Support\RichTextConverter)->convert($metafield['value'], true);


```

## Hooks

`ImportSingleProductJob` provides two [Hooks](https://statamic.dev/extending/hooks) so you can tap into the import pipeline without overriding the job.

#### import-product-query hook

Runs just before the product GraphQL query is sent to Shopify. Use it to add or change fields on the query, e.g. to pull in additional data.

```php
\Thoughtco\Shopify\Jobs\ImportSingleProductJob::hook('import-product-query', function ($payload, $next) {
    // $payload->query        — the GraphQL query string about to be sent
    // $payload->productId    — the Shopify product ID being imported
    // $payload->storeHandle  — the store handle in multi-store mode, otherwise null

    $payload->query = str_replace('descriptionHtml', 'descriptionHtml seo { title }', $payload->query);

    return $next($payload);
});
```

#### import-product-data hook

Runs just before the imported data is merged onto the Statamic entry. Use it to modify, add, or remove fields before they're saved.

```php
\Thoughtco\Shopify\Jobs\ImportSingleProductJob::hook('import-product-data', function ($payload, $next) {
    // $payload->data        — the array of data about to be merged onto the entry
    // $payload->entry       — the Statamic entry (existing or newly made) being imported into
    // $payload->product     — the raw product data returned by Shopify

    $data = $payload->data;
    $data['title'] = strtoupper($data['title']);
    $payload->data = $data;

    return $next($payload);
});
```

> [!NOTE]
> Because `$payload->data` is an array exposed through a magic property, you can't modify it in place (e.g. `$payload->data['title'] = '...'`). Assign it to a local variable, change it, then assign it back to `$payload->data` as shown above.
